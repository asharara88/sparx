## Branch and pull request rules

- Work on the branch the session names (`claude/<session>`); never push to any other
  branch, never to `main` directly.
- Commit messages end with the two attribution trailers the session's system reminder
  gives (`Co-Authored-By` and `Claude-Session`). PR bodies end with the Claude Code line
  and the session link. Every GitHub comment ends with the `_Generated by Claude Code_`
  footer. No model names anywhere in commits, PR text or code.
- Open every PR as a draft. Mark it ready only when it is a real change worth one review.
- **Codex costs money.** Marking a draft ready triggers a Codex review on its own, so
  never also comment `@codex review` on it (that doubled the cost for weeks). One review
  per real PR; no re-review after fixing its findings (verify the fix yourself and merge
  once CI is green and Codex is clear, or has posted nothing 25 minutes after the
  review started). Small changes (docs, CI, dependency bumps, one-file fixes) get no
  review: GitHub refuses to merge a draft, so mark ready and merge in the same breath.
  The only full cure is turning off automatic reviews in the Codex GitHub settings; Mido
  has been told.
- Codex's findings have all been real so far. Fix each, reply on its thread naming the
  commit, resolve the thread.
- Squash-merge yourself; after the merge reset the working branch onto `main`
  (`git fetch origin main && git checkout -B <branch> origin/main && git push --force-with-lease`).
- Before any push: run the tree's checks above. For `family/` the build needs
  `NEXT_PUBLIC_SUPABASE_URL=https://example.supabase.co NEXT_PUBLIC_SUPABASE_ANON_KEY=sb_publishable_localscreenshotsonly000`,
  and it writes `family/AGENTS.md`, which is never committed: `rm -f family/AGENTS.md` after.
- Push fewer, larger commits: every push costs a Vercel preview build and a CI run.
- Keep one `send_later` check-in while a PR waits on CI; cancel it when the PR merges.

## The database

- Migrations live in `family/supabase/migrations`, numbered `20261010NNNN00`, applied in
  filename order. They reach the live project through the Supabase GitHub integration
  when `main` moves; verify with the Supabase MCP afterwards (`list_migrations`, then a
  count of the objects the migration makes). Never edit an applied migration.
- `family/supabase/tests/rls_test.sql` is the database test suite (`npm run db:test`
  against a local Postgres: `pg_ctlcluster 16 main start`, then
  `PSQL="psql -h localhost -U postgres" PGPASSWORD=postgres npm run db:test`). Every new
  function or policy gets checks there, as the signed-in role, including the refusals.
- Ownership rules the suite enforces: definer functions belong to `app_rls` unless they
  must see across homes or read `auth.users`; those stay with `postgres` and must be
  added to the exception lists in the suite. No `app_rls` function may name the `auth`
  schema. A function only signed-in users may call gets
  `revoke execute ... from public, anon` (functions are public by default).
- Assertions that read a table directly must run after `reset role`: row security hides
  other homes' rows from the signed-in role and the assertion fails for the wrong reason.
- Supabase MCP `execute_sql`: a multi-statement batch is one transaction, and a failing
  trailing select rolls back the lot. A bare `delete` on `members` or `household` hangs
  until the tool's timeout; use a `do $$ ... $$` block that sets `request.jwt.claims` and
  calls the app's own RPCs instead.

## The app

- **Before changing anything a person sees, read `family/docs/DESIGN.md`** (the design
  bible: one screen one question, one alert at a time, one number per card, budgets per
  screen). Measure with `node family/scripts/ui-audit.mjs <route>` in screenshot mode and put
  the before/after numbers in the PR. A screen does not grow without something leaving it.
- A function exported from a `"use client"` file cannot be called while rendering a
  server page (React refuses, the page answers 500). Shared helpers live in `lib/`.
  This took the Members screen down for a day.
- Screenshot mode runs the app against a local Postgres with no Supabase:
  build the database (`run-local.sh` steps or the stub, the migrations,
  `tests/01_test_household.sql`, `tests/demo_data.sql`), start
  `FAMILY_LOCAL_DB=<db> npx next dev` with the two example env values above, and
  open pages with a `shot_as=<member uuid>` cookie. Playwright lives at the repo root
  (`/home/user/sparx/node_modules/playwright`); launch Chromium with
  `executablePath: "/opt/pw-browsers/chromium-1194/chrome-linux/chrome"` (do not run
  `playwright install`). A sweep of every route as admin, carer and an account in no
  home is cheap and found a real crash; client-side taps do not work in this mode.
- The sandbox cannot reach `elnunu.com` or `*.supabase.co` directly (curl answers 000);
  the Supabase MCP works, the Vercel MCP needs team scope the connector may lack.
